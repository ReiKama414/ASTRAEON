# ASTRAEON｜電影級 3D 視覺重製

> 此為上一輪的階段紀錄。2026-09-20 新的六階段順序與 Dreamlike Universe Showcase 驗收，以 [DREAMLIKE_REBUILD_PLAN.md](DREAMLIKE_REBUILD_PLAN.md) 為準。

## 參考與現況診斷

使用者提供的六張圖片分別傳達：低對比軌道與立體行星、藍紫色旋臂與星際氣體、具有扭曲感的黑洞吸積盤、近地地平線與薄大氣、較接近物理攝影的黑洞，以及高密度暖色星系核心。圖片用於構圖、光影與材質方向，不當作場景貼圖或版型來源。

原有程式已使用 React Three Fiber 和真正的 Three.js Mesh；問題不是 CSS 冒充 3D。主要落差在於首頁旋臂只靠點粒子、缺少連續氣體與暗塵帶；地球受到偏亮的全局光，夜光貼圖固定疊加而沒有日夜遮罩；近地模式的相機看向球心，結果只是放大的地表；太陽系以佔畫面的軌道線和極小行星為主；UI 固定導覽欄與底列削弱了場景。可重用的資料、搜尋、收藏、天體選取、相機控制、貼圖載入與 WebGL 退化流程保留。

## 共用渲染決策

```ts
type VisualTier = 'cinematic' | 'balanced' | 'mobile';
type SceneProfile = {
  id: string;
  tier: VisualTier;
  renderScale: number;
  maxParticles: number;
  textureEdge: 2048 | 4096 | 8192;
  bloom: boolean;
  volumetricSteps: number;
  orbitOpacity: number;
};
type QualitySample = { frameMsP50: number; frameMsP95: number; gpuTextureMB: number; drawCalls: number };
```

桌面 1080p 目標 60 fps 中位數、p95 幀時 ≤25 ms、GPU 紋理 ≤512 MB、draw calls ≤300；手機 390×844 目標 30 fps 中位數、p95 幀時 ≤45 ms、GPU 紋理 ≤192 MB、draw calls ≤150。先調 DPR、粒子 overdraw、體積採樣與貼圖格式，再降低主天體尺寸或材質。所有天體詳細模式與總覽模式分開選 LOD，視覺半徑與物理尺度分開存放。

## Phase 3｜太陽系、太陽與其餘行星

1. 將目前的平面軌道構圖改為透視斜角 3D 空間；低對比軌道預設弱化，可切換，八顆行星只在總覽使用遠距 LOD。
2. 太陽使用獨立表面 shader：多頻流動噪聲、日面斑駁、日冕視角層與範圍受控的 bloom；太陽作為太陽系主要照明來源。
3. 為水星、金星、火星、木星、土星、天王星、海王星建立各自材質與環境設定。木星驗收大紅斑可辨；土星環使用具透明度的分層材質與正確前後遮擋。
4. 點擊行星時從總覽相機平滑轉入詳細場景，進場才載入高解析貼圖；離開時釋放非共用 GPU 資源。

驗收：總覽斜角具空間深度，軌道不主導畫面；每顆行星近景能憑材質辨識；太陽不再是橘色常色球；至少完成桌面總覽、木星、土星、太陽與手機總覽截圖；量測達共用預算。風險：太陽 bloom 過曝、土星透明排序、巨行星貼圖授權與高解析貼圖記憶體。

## Phase 4｜星系、星雲、黑洞與幻想天體

1. 把 Phase 1 的旋臂、氣體與塵埃結構提升為銀河系及仙女座專屬變體，分別設定核心色溫、臂距、傾角與 LOD；建立近／中／遠景相機敘事。
2. 星雲採深度分層的程序化噪聲片、粒子與低步數體積近似；以深度淡化和抖動避免平板疊圖。
3. 黑洞建立事件視界遮擋、吸積盤 Doppler 色差與背景折射近似 shader；UI 明示視覺模擬，不能宣稱廣義相對論數值解。
4. 海洋、熔岩、冰晶、神秘星球各有獨立程序化材質、光照與動畫，而非共用發光球模板。

驗收：銀河和仙女座可憑結構分辨；星雲前後層隨鏡頭位移產生視差；黑洞背景出現可見扭曲與盤的遮擋；幻想星球有四種明確視覺語言；所有場景完成桌面與手機截圖和共用效能量測。風險：透明物件排序、shader 可攜性、粒子填充率與 WebGL1／低階 GPU 的降級路徑。

## Phase 5｜介面、鏡頭、效能與手機

1. 改造左導航為可收合的浮層；底部改為精簡的真實天體縮圖列。加入一鍵隱藏全部 UI，資訊面板避開當前主體。
2. 統一 Orbit、Free Fly、Focus、Follow、Tour、Surface 的相機狀態機、插值曲線與中斷規則；尺度切換時使用中繼鏡頭，避免穿模和瞬移。
3. 實作場景邊界的貼圖預取、LRU 緩存、KTX2/適當壓縮格式與載入進度；加入按裝置、GPU 時間及幀率的畫質級別切換。
4. 手機使用獨立粒子與 shader 採樣預算；驗證單指環繞、雙指縮放、觸控目標與安全區。完善 context lost / restored 流程、reduced motion 與鍵盤導航。
5. 建立固定視口截圖清單與測試設備矩陣；完成至少 20 次場景往返、10 分鐘互動及記憶體觀察。

驗收：使用者首次進站先看見主天體，導航可完全收起；模式切換可中斷且不穿模；手機內容可操作、主要天體不被控件遮住；通過共用效能預算與錯誤恢復測試。風險：UI 與 3D 互動事件競爭、資產快取佔用 GPU 記憶體、移動裝置瀏覽器差異。
